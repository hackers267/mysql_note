`Round`是*MySQL*中用于四舍五入的函数。在通常情况下，`Round`函数可以接收一个或2个参数。第一个参数是被四舍五入的数字,第二个参数是保留的小数位数。在通常的情况下，`Round`的表示是符合我们的预期的，比如下面的几种情况：

```sql
SELECT Round(123.456, 1); # 123.5
SELECT Round(123.446, 1); # 123.4
```

# 异常的四舍五入

但是，在一些情况下，`Round`会表现出不同于我们通常期望的行为，比如下面的情况：

```sql
SELECT Round(0.025, 2); # 0.03
SELECT Round(25E-3, 2); # 0.02
```
之所以出现这种情况，是因为MySQL在处理四舍五入的时候，会根据不同的数据类型来执行不同的情况：

- 对于 **精确值** ,`Round`会使用远离0的策略来进行四舍五入：对于比0大的值，如果小数部分的*.5* 或更大会把数值向上加入否则就把对应数据舍去，而对于小于0的值，如果小数部分为*.5*或更大，会把数值向下舍去，否则会加数据。使其保留的值比原来的值距离0的位置更远。
- 对于 **近似值**,`Round`其结果依赖于`C`库。在大多数系统中，这意味着使用**就近偶数**原则。即把值向最近的偶数性的数取整。如在要求保留1位小数点时，把*0.15*取为*0.2*，把*0.25*也取为*0.2*(因为*0.15*和*0.25*最近的偶数性的值都是*0.2*)

# 异常的精度值

我们知道，在使用`Round`的时候，我们可以通过第二个参数来指定要保留的小数位数。但是并不是在所有的情况下，最后的显示都是我们要求的小数位置。因为`Round`的返回值数据取决下其第一个参数的类型。比如下面的示例：

```sql
SELECT ROUND(-1.23);# -1
SELECT ROUND(-1.58);# -2
SELECT ROUND(1.58);# 2
SELECT ROUND(1.298, 1);# 1.3
SELECT ROUND(1.298, 0);# 1
SELECT ROUND(23.298, -1);# 20
SELECT ROUND(.12345678901234567890123456789012345, 35);# 0.123456789012345678901234567890
SELECT ROUND(150, 2); # 150
```

我们看到在上面的示例中，大部分的返回值都是我们要求的小数位数。但是最后一个的返回值*150*并不是*150.00*。这是因为在`Round`中，第一个返回值的类型是`Integer`类型，其结果也是`Integer`，返回没有小数位数。在`MySQL8`之前没有对应的文档说明，但是在*8.0.21*及以后的版本中，`Round`的返回值会遵守以下的规则：

- 如果第一个参数是任意的`integer`类型，那么返回值总是`BIGINT`类型
- 如果第一个数据是任意的浮点数类型，那么返回值总是`DOUBLE`类型
- 如果第一个参数是`DECIMAL`类型，那么返回值总是`DECIMAL`类型
- 当第二个参数是一个常量时，返回值会复制类型属性(`DECIMAL`类型除外)
